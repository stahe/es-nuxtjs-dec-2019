    5. Ejemplo [nuxt-02]: Páginas del servidor y del cliente

    En este proyecto, demostramos:

    • que la página generada por el cliente puede tener un aspecto diferente a la recibida del servidor. Esto da lugar a un cambio rápido de página que el usuario nota, lo cual es perjudicial para la usabilidad de la aplicación. Por lo tanto, es una opción que conviene evitar;
    • una solución para que la página del lado del cliente recree la misma página que la enviada por el servidor;

    El proyecto [nuxt-02] se crea inicialmente clonando el proyecto [nuxt-01].

    Se añade una carpeta [store] al proyecto, junto con dos nuevas páginas. Volveremos sobre esto más adelante.

    5.1. La página [index]

    5.2. La página [page1]

    5.2.1. El almacén [Vuex]

    Añadimos una carpeta [store] al proyecto [nuxt-02]:

    La presencia de esta carpeta hace que [nuxt] implemente automáticamente un almacén [Vuex]. El archivo [index.js] implementa este almacén. A continuación se muestra el contenido del archivo [index.js]:

    
export const state = () => ({
  counter: 0
})
 
export const mutations = {
  increment(state, inc) {
    state.counter += inc
  }
}

    [nuxt] implementa un almacén [Vuex] basado en el contenido de [index.js]:

    • líneas 1–3: definición del [state] del almacén. Este estado es devuelto por una función. Aquí, el estado solo tiene una propiedad, el contador de la línea 2. La función exportada debe llamarse [state];
    • líneas 5-9: las operaciones posibles sobre el estado del almacén. Estas se denominan [mutaciones]. Aquí, la mutación [increment] incrementa la propiedad [contador] en una cantidad [inc]. El objeto exportado debe llamarse [mutaciones];

    El [store] de Vuex implementado por [nuxt] está disponible en varios lugares. En las vistas, está disponible en la propiedad [this.$store].

    5.2.2. El código de la página

    Al igual que la página [index], la página [page1] mostrará un valor: el contador del almacén Vuex:

  <Layout :left="true" :right="true">

    • líneas 38-40: el servidor incrementará el contador en 25;
    • línea 42: tanto el servidor como el cliente mostrarán el valor del contador;
    • línea 7: se muestra el valor del contador;

    Al leer este código, hay que tener en cuenta dos cosas:

    • el código ejecutado es el mismo tanto para el servidor como para el cliente;
    • el objeto [this] no es el mismo: hay un [this] del lado del servidor y un [this] del lado del cliente;

    Queremos saber si el [this.$store] del servidor es el mismo que el [this.$store] del cliente. Dado que el servidor se ejecuta primero (cuando se inicia la aplicación), esto se reduce a preguntarse: ¿se pasa al cliente el [store] inicializado por el servidor?

    5.3. La página [page2]

    En la página [page2], mostramos otra forma de:

    • el servidor incluya información calculada en la página;
    • el cliente no modifica esta información;

    5.3.1. El código de la página

    El código de la página [página2] cambia de la siguiente manera:

    
<!-- page2 -->
<template>
  <Layout :left="true" :right="true">
    <!-- navigation -->
    <Navigation slot="left" />
    <!-- message -->
    <b-alert slot="right" show variant="secondary"> Page 2 - value = {{ value }} </b-alert>
  </Layout>
</template>
 
<script>
/* eslint-disable no-console */
/* eslint-disable nuxt/no-timing-in-fetch-data */
 
import Navigation from '@/components/navigation'
import Layout from '@/components/layout'
 
export default {
  name: 'Page2',
  // components used
  components: {
    Layout,
    Navigation
  },
  asyncData(context) {
    // who executes this code?
    console.log('asyncData, client=', process.client, 'serveur=', process.server)
    // only for the server
    if (process.server) {
      // we return a promise
      return new Promise(function(resolve, reject) {
        // this is normally an asynchronous function
        // we simulate it with a one-second wait
        setTimeout(() => {
          // this result will be included in the properties of [data]
          resolve({ value: 87 })
          // log
          console.log('asynData terminée')
        }, 1000)
      })
    }
  },
  // life cycle
  beforeCreate() {
    // client and server
    console.log('[page2 beforeCreate]')
  },
  created() {
    // client and server
    console.log('[page2 created]')
  },
  beforeMount() {
    // customer only
    console.log('[page2 beforeMount]')
  },
  mounted() {
    // customer only
    console.log('[page2 mounted]')
  }
}
</script>
    • línea 7: la página muestra el valor de una propiedad llamada [value];
    • la propiedad [value] no existe como parte de un objeto devuelto por la función [data]. Aquí, esta función no existe. La propiedad [value] se crea dinámicamente en la línea 36;
    • línea 25: la función [asyncData] es una función de [nuxt]. Como su nombre indica, suele ser una función asíncrona. Su función habitual es recuperar datos externos. [nuxt] se asegura de que la página no se envíe al navegador del cliente hasta que la función [asyncData] haya renderizado sus datos asíncronos;
    • La función [asyncData] recibe el contexto [nuxt] como parámetro. Este objeto es muy completo y proporciona acceso a mucha información sobre la aplicación [nuxt]. Lo veremos en las siguientes secciones;
    • Línea 31: Implementamos la función [asyncData] utilizando una [Promise] (véase el documento |Introducción a ECMAScript 6 con ejemplos|). El constructor de esta clase acepta una función asíncrona como parámetro que:
      • indica éxito devolviendo datos con la función [resolve]. El objeto devuelto por esta función se incluye automáticamente en las propiedades [data] de la página;
      • señala un fallo devolviendo un error mediante la función [reject];

    }
  },
  created() {
    // client and server
    this.value = this.$store.state.counter
    console.log('[page4 created], value=', this.value)
  },
  beforeMount() {
    // customer only
    console.log('[page4 beforeMount]')
  },
  mounted() {
    // customer only
    console.log('[page4 mounted]')
  }
}
</script>
    • línea 30: lo que antes se hacía en la función [fetch] ahora se hace en el método [beforeCreate]. Utilizamos el par async (línea 30) / await (línea 36) para esperar a que termine la función asíncrona;
    • línea 36: recuperamos el resultado de la función asíncrona devuelta en la línea 41 tras 10 segundos (línea 42);
    • líneas 50–54: en el método [created], que se ejecuta tanto en el servidor como en el cliente, el contador se asigna a la propiedad [value] de la página;

    5.7. Resumen

    A partir de nuestras diversas pruebas, podemos concluir lo siguiente:

    • si la página [index] debe contener datos externos, el servidor puede recuperar estos datos mediante la función [asyncData];
    • si el servidor necesita inicializar un almacén [Vuex] con datos externos al cargar la página [index], lo hará en la función [fetch];
    • la página generada por el servidor y la página generada por el cliente deben ser idénticas para evitar el efecto de «parpadeo» causado por la sustitución visual, por parte de la página del lado del cliente, de la página enviada por el servidor y mostrada inicialmente;
