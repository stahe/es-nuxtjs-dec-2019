    13. Ejemplo [nuxt-10]: asyncData y loading

    La función [asyncData] en una página permite cargar de forma asíncrona datos que suelen ser externos. [nuxt] espera a que finalice la función [asyncData] antes de iniciar el ciclo de vida de la página. Por lo tanto, esta solo se muestra una vez obtenidos los datos externos. Se ejecuta tanto en el servidor como en el cliente con las siguientes reglas:

    • cuando la página se solicita directamente al servidor, solo el servidor ejecuta la función [asyncData];
    • luego, durante la navigation del cliente, solo el cliente ejecuta la función [asyncData];

    Al final, solo uno de los dos, el cliente o el servidor, ejecuta la función. Por otra parte, cuando es el cliente quien ejecuta la función [asyncData], [nuxt] muestra una barra de progreso que se puede configurar.

    La función [asyncData] permite entregar a los motores de búsqueda páginas con sus datos, lo que las hace más relevantes.

    El ejemplo [nuxt-10] se obtiene inicialmente copiando el proyecto [nuxt-01]:

    Solo cambia la página [page1].

    13.1. La página [page1]

    El código de la página [page1] es el siguiente:

    
<!-- ver nº 1 -->
<template>
  <Layout :left="true" :right="true">
    <!-- navigation -->
    <Navigation slot="left" />
    <!-- mensaje-->
    <b-alert slot="right" show variant="primary"> Page 1 -- result={{ result }} </b-alert>
  </Layout>
</template>
 
<script>
/* eslint-disable no-console */
/* eslint-disable nuxt/no-timing-in-fetch-data */
 
import Navigation from '@/components/navigation'
import Layout from '@/components/layout'
 
export default {
  name: 'Page1',
  // componentes utilizados
  components: {
    Layout,
    Navigation
  },
  // datos asíncronos
  asyncData(context) {
    // registrar
    console.log('[page1 asyncData started]')
    // hacemos una promesa
    return new Promise(function(resolve, reject) {
      // simulamos una función asíncrona
      setTimeout(function () {
        // hacemos el resultado asíncrono - un número aleatorio aquí
        resolve({ result: Math.floor(Math.random() * Math.floor(100)) })
        // registrar
        console.log('[page1 asyncData finished]')
      }, 5000)
    })
  },
 
  // ciclo vital
  beforeCreate() {
    console.log('[page1 beforeCreate]')
  },
  created() {
    console.log('[page1 created]')
  },
  beforeMount() {
    console.log('[page1 beforeMount]')
  },
  mounted() {
    console.log('[page1 mounted]')
  }
}
</script>
    • líneas 26-39: la función [asyncData]. Ya hemos estudiado esta función (véase el párrafo del enlace). Se ejecuta antes del ciclo de vida de la página. Por este motivo, no se puede utilizar la palabra clave [this] en la función;
    • línea 30: debe devolver una promesa [Promise] o utilizar la sintaxis async / await;
    • líneas 32-37: la función asíncrona de la promesa se simula con una espera de 5 segundos (línea 37);
    • línea 34: el resultado de la función asíncrona se devuelve en forma de un objeto {result :...}. El objeto asíncrono devuelto por la función [asyncData] se integra en el objeto [data] de la página. Por eso el objeto [result] está disponible en la línea 7 de la plantilla, aunque la página no hubiera definido el objeto [data];

    13.2. Configuración de la barra de progreso de [asyncData]

    Cuando la página [page1] es el destino de un navigation dentro del cliente (modo SPA), el cliente ejecuta la función [asyncData] y [nuxt] muestra entonces una barra de progreso que oculta cuando la función [asyncData] ha devuelto su resultado. La propiedad [loading] del archivo [nuxt.config.js] permite configurar esta barra:

    
loading: {
    color: 'blue',
    height: '5px',
    throttle: 200,
    continuous: true
},

    Por defecto, la imagen de espera de [nuxt] es una barra de progreso que ocupa todo el ancho de la página. Esta barra tiene un color y un grosor. La línea de color crece progresivamente del 0 % al 100 % de su tamaño, más o menos rápido según la duración de la espera.

    • línea 2: establece el color de la barra de progreso;
    • línea 3: establece el grosor de la barra en píxeles;
    • línea 4: [throttle] es el retraso en milisegundos antes de que comience la animación. Esto evita que aparezca una imagen de animación cuando la función [asyncData] devuelve su resultado rápidamente;
    • línea 5: [continuous] establece el comportamiento de la animación de la barra de progreso. Por defecto, la barra crece progresivamente del 0 % al 100 % de su tamaño, más o menos rápido según la duración de la espera. Con [continuous:true], la barra de color crece a una velocidad constante del 0 al 100 % de su tamaño, y luego vuelve a empezar mientras la función [asyncData] no haya devuelto su resultado;
