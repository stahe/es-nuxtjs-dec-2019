    Todos estos son documentos para principiantes. Los artículos siguen una secuencia lógica, pero están vagamente relacionados entre sí:

    • el documento [1] presenta el lenguaje PHP 7. Los lectores interesados únicamente en PHP y no en el JavaScript tratado en los siguientes artículos deberían detenerse aquí;
    • Los documentos [2–4] tienen como objetivo crear un cliente JavaScript para el servidor de cálculo de impuestos desarrollado en el documento [1];
    • Los marcos de trabajo de JavaScript [vue.js] y [nuxt.js] de los artículos 3 y 4 requieren conocimientos de las últimas versiones de ECMAScript, concretamente la versión 6. Por lo tanto, el documento [2] está destinado a quienes no estén familiarizados con esta versión de JavaScript. Hace referencia al servidor de cálculo de impuestos creado en el documento [1]. Por lo tanto, los lectores del [2] tendrán que volver a consultar el documento [1] en algunas ocasiones;
    • Una vez dominado ECMASCRIPT 6, podemos pasar al marco VUE.JS, que permite la creación de clientes JavaScript que se ejecutan en un navegador en modo SPA (aplicación de página única). Este es el documento [3]. Hace referencia tanto al servidor de cálculo de impuestos creado en el documento [1] como al código del cliente JavaScript independiente creado en [2]. Por lo tanto, los lectores de [3] tendrán que consultar en ocasiones los documentos [1] y [2];
    • Una vez que domines VUE.JS, podrás pasar al marco NUXT.JS, que te permite crear clientes JavaScript que se ejecutan en un navegador en modo SSR (renderizado del lado del servidor). Se refiere al servidor de cálculo de impuestos creado en el documento [1], al código de cliente JavaScript independiente creado en [2] y a la aplicación [vue.js] desarrollada en el documento [3]. Por lo tanto, los lectores de [4] tendrán que consultar ocasionalmente los documentos [1], [2] y [3];

    Este documento continúa el trabajo realizado en el documento [3] utilizando el marco Vue.js.

    Esta sección se centra en la siguiente arquitectura:

    • En [1], un navegador web muestra páginas web [5, 7] procedentes de un servidor [3] destinadas a un usuario. Estas páginas contienen JavaScript que implementa un cliente para un servicio de datos web [2], así como un cliente para un servidor de fragmentos de páginas web [3];
    • En [2], el servidor web actúa como servidor de datos. Puede estar escrito en cualquier lenguaje de programación. No genera páginas web en el sentido tradicional (HTML, CSS, JavaScript), salvo quizá la primera vez. Sin embargo, esa primera página puede obtenerse de un servidor web tradicional [3] (no de un servidor de datos). El JavaScript de la página inicial generará entonces las distintas páginas web de la aplicación recuperando los datos [4] que se van a mostrar del servidor web, que actúa como servidor de datos [2]. También puede recuperar fragmentos de páginas web [5] para dar formato a estos datos del servidor de páginas web [3];
    • en [4], el usuario inicia una acción;
    • en [6,7]: recibe datos formateados por un fragmento de página web;

    El marco [nuxt.js] |https://fr.nuxtjs.org/| nos permitirá implementar el siguiente flujo de trabajo:

    • La primera página de la aplicación es servida por el servidor [node.js] [3]. Además, el resto de páginas de la aplicación también están alojadas en este mismo servidor. Se sirven cuando el usuario escribe manualmente su URL en el navegador. Estas páginas incorporan una aplicación [vue.js] (aproximadamente);
    • una vez que la primera página se ha cargado en el navegador, la aplicación se comporta como una aplicación [Vue.js] estándar. En nuestro diagrama anterior, se comunicará entonces con el servidor de datos [2];

    En definitiva, la aplicación se comporta como una aplicación [Vue.js], salvo en la primera página y cuando el usuario introduce manualmente las URL. En estos casos, la página se recupera del servidor [3]. Cuando un motor de búsqueda solicita las distintas páginas de la aplicación, recibe las páginas del servidor [3]. Estas páginas pueden haber sido optimizadas para SEO (Search Engine Optimization). En una aplicación [Vue.js], el motor de búsqueda recibe una página con escaso valor SEO. Por ejemplo, en la aplicación cliente para el servidor de cálculo de impuestos sobre documentos [3], la página recibida por el navegador al iniciar la aplicación era la siguiente:

    
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width,initial-scale=1.0">
    <link rel="icon" href="/client-vuejs-impot/favicon.ico">
    <title>vuejs</title>
  <link href="/client-vuejs-impot/app.js" rel="preload" as="script"></head>
  <body>
    <noscript>
      <strong>We're sorry but vuejs doesn't work properly without JavaScript enabled. Please enable it to continue.</strong>
    </noscript>
    <div id="app"></div>
    <!-- built files will be auto injected -->
  <script type="text/javascript" src="/client-vuejs-impot/app.js"></script></body>
</html>

    Esta es la única página que carga el navegador. El resto de páginas de la aplicación se generan dinámicamente mediante JavaScript sin la ayuda del navegador. Algunos motores de búsqueda se conforman con esta página. Otros van más allá y ejecutan el JavaScript contenido en la página (línea 9 anterior). A continuación, se obtiene otra página. Esta página puede contener una operación asíncrona para recuperar los datos que mostrará. En este caso, los motores de búsqueda no esperan. Nos quedamos entonces con una página incompleta. Quizá recuerdes que este es el caso de nuestro cliente [Vue.js] en el servidor de cálculo de impuestos: de forma asíncrona, mientras se carga la primera página, inicializa una sesión JSON con el servidor de cálculo de impuestos. En este caso concreto, esto no afecta a la página recuperada por el motor de búsqueda. Para otras aplicaciones, esto podría ser perjudicial en términos de SEO.

    Con [nuxt.js], podemos ofrecer una página más significativa al motor de búsqueda para cada página de la aplicación.
