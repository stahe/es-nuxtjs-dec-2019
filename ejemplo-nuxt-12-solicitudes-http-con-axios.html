    15. Ejemplo [nuxt-12]: solicitudes HTTP con axios

    15.1. Introducción

    En este nuevo ejemplo, veremos cómo en las funciones [asyncData] se pueden realizar solicitudes HTTP con la biblioteca [axios]. Además, utilizaremos conceptos ya adquiridos:

    • el uso de plugins del ejemplo [nuxt-06]:
    • la persistencia del almacén en una cookie de sesión del ejemplo [nuxt-06];
    • el control de navigation con middlewares del ejemplo [nuxt-09];
    • la gestión de errores del ejemplo [nuxt-11];

    La arquitectura del ejemplo será la siguiente:

    • la aplicación [nuxt] se almacenará en el servidor [node.js] [3], se descargará mediante el navegador [1], que posteriormente la ejecutará;
    • tanto el cliente [nuxt] [1] como el servidor [nuxt] [3] realizarán consultas HTTP al servidor de datos [2]. Este servidor será el servidor de cálculo de impuestos desarrollado en la parte PHP 7. Utilizaremos su última versión, version, la version 14, con las consultas CORS autorizadas;

    La arquitectura del ejemplo se puede simplificar de la siguiente manera:

    • en [1], el servidor [node.js] envía las páginas [nuxt] al navegador [2]. Es la capa [web] [8] del servidor la que entrega estas páginas. Para entregar la página, el servidor pudo haber solicitado datos externos al servidor de datos [3]. Es la capa [DAO] [9] la que realiza las solicitudes HTTP necesarias;
    • cada vez que se realiza una llamada de página al servidor [node.js][1], el navegador [2] recibe la totalidad de la aplicación [nuxt], que se ejecutará entonces en modo SPA. El bloque [UI] (Interfaz de usuario) [4] muestra las páginas [vue.js] al usuario. Las acciones de este o el ciclo de vida natural de las páginas pueden provocar llamadas de datos externos al servidor de datos [3]. Es la capa [DAO] [5] la que realiza entonces las consultas HTTP necesarias;

    15.5.1. La capa [dao] del servidor [nuxt]

    El servidor [node.js] [1] utilizará la capa [dao] descrita en el documento |Introducción al marco VUE.JS a modo de ejemplo|. A continuación recordamos su código:

    
'use strict';
 
// importaciones
import qs from 'qs'
 
class Dao {
 
  // fabricante
  constructor(axios) {
    this.axios = axios;
    // cookie de sesión
    this.sessionCookieName = "PHPSESSID";
    this.sessionCookie = '';
  }
 
  // iniciar sesión
  async  initSession() {
    // opciones de consulta HHTP [get /main.php?action=init-session&type=json]
    const options = {
      method: "GET",
      // parámetros URL
      params: {
        action: 'init-session',
        type: 'json'
      }
    };
    // ejecución de la solicitud HTTP
    return await this.getRemoteData(options);
  }
 
  async  authentifierUtilisateur(user, password) {
    // opciones de consulta HHTP [post /main.php?action=authentifier-utilisateur]
    const options = {
      method: "POST",
      headers: {
        'Content-type": "application/x-www-form-urlencoded",
      },
      // cuerpo de POST
      data: qs.stringify({
        user: user,
        password: password
      }),
      // parámetros URL
      params: {
        action: 'authentifier-utilisateur'
      }
    };
    // ejecución de la solicitud HTTP
    return await this.getRemoteData(options);
  }
 
  async getAdminData() {
    // opciones de consulta HHTP [get /main.php?action=get-admindata]
    const options = {
      method: "GET",
      // parámetros URL
      params: {
        action: 'get-admindata'
      }
    };
    // ejecución de la solicitud HTTP
    const data = await this.getRemoteData(options);
    // resultado
    return data;
  }
 
  async  getRemoteData(options) {
    // para la cookie de sesión
    if (!options.headers) {
      options.headers = {};
    }
    options.headers.Cookie = this.sessionCookie;
    // ejecución de la solicitud HTTP
    let response;
    try {
      // solicitud asíncrona
      response = await this.axios.request('main.php', options);
    } catch (error) {
      // el parámetro [error] es una instancia de excepción - puede tomar varias formas
      if (error.response) {
        // la respuesta del servidor está en [error.response]
        response = error.response;
      } else {
        // reiniciar el error
        throw error;
      }
    }
    // response es la respuesta HTTP completa del servidor (cabeceras HTTP + respuesta propiamente dicha)
    // recuperar la cookie de sesión si existe
    const setCookie = response.headers['set-cookie'];
    if (setCookie) {
      // setCookie es una matriz
      // buscar la cookie de sesión en esta tabla
      let trouvé = false;
      let i = 0;
      while (!trouvé && i < setCookie.length) {
        // buscar la cookie de sesión
        const results = RegExp('^(' + this.sessionCookieName + '.+?);').exec(setCookie[i]);
        if (results) {
          // guardamos la cookie de sesión
          // eslint-disable-next-line require-atomic-updates
          this.sessionCookie = results[1];
          // encontramos
          trouvé = true;
        } else {
          // punto siguiente
          i++;
        }
      }
    }
    // la respuesta del servidor está en [response.data]
    return response.data;
  }
}
 
// exportación de clases
export default Dao;

    En cuanto a la cookie de sesión, debemos considerar dos capas [dao] separadas:

    • la del navegador;
    • la del servidor;

    Tendremos que gestionar tres cookies de sesión:

    1. la que se intercambia entre el cliente [nuxt] y el servidor PHP 7;
    2. la que se intercambia entre el servidor [nuxt] y el servidor PHP 7;
    3. la intercambiada entre el cliente [nuxt] y el servidor [nuxt];

    Nos aseguraremos de que la cookie de sesión con el servidor PHP sea la misma para el cliente y el servidor [nuxt]. Llamaremos a esta cookie «cookie de sesión PHP». Esta es la cookie de los casos 1 y 2. Llamaremos «cookie de sesión [nuxt]» a la cookie del caso 3. Por lo tanto, tendremos dos sesiones:

    • una sesión PHP con la cookie de sesión PHP;
    • una sesión [nuxt] con la cookie de sesión [nuxt];

    ¿Por qué utilizar la misma cookie para las sesiones PHP del cliente y del navegador [nuxt]? Queremos que la aplicación pueda comunicarse con el servidor PHP indistintamente con el cliente o con el servidor [nuxt]:

    • si una acción A del servidor [nuxt] pone al servidor PHP en un estado E, este estado se refleja en la sesión PHP mantenida por el servidor PHP;
    • utilizando la misma cookie de sesión PHP que el servidor, una acción B del cliente [nuxt] que siguiera a la acción A del servidor [nuxt] encontraría al servidor PHP en elestado E dejado por el servidor [nuxt] y, por lo tanto, podría basarse en el trabajo ya realizado por el servidor [nuxt];
    • si tras la acción B del cliente [nuxt] se produce una acción C del servidor [nuxt], por la misma razón que antes, esta acción podrá basarse en el trabajo realizado por la acción B del cliente [nuxt];

    Para que el navegador del cliente [nuxt] pueda comunicarse con el servidor PHP de cálculo de impuestos, utilizaremos el version 14 de este servidor, que autoriza las llamadas entre dominios, es decir, las realizadas desde un navegador hacia el servidor PHP. Las llamadas del servidor [nuxt] al servidor PHP no son, por su parte, llamadas entre dominios. Este concepto solo existe para las llamadas realizadas desde un navegador.

    La gestión de la cookie de sesión PHP anterior no es adecuada para el servidor [nuxt]: su capa [dao] se instancia con cada nueva solicitud realizada al servidor [nuxt]. Recordemos que solicitar una página al servidor [nuxt] equivale a reiniciar la aplicación [nuxt]. Así, cuando, al finalizar la primera solicitud realizada al servidor de datos por el servidor [nuxt], se inicializa la cookie de sesión PHP de la capa [dao], este valor se pierde en la siguiente solicitud HTTP del mismo servidor [nuxt], ya que, entretanto, se ha vuelto a crear su capa [dao], se ha vuelto a ejecutar el constructor y se ha reiniciado la cookie de sesión PHP con la cadena vacía (línea 6);

    Una solución es utilizar otro constructor para la capa [dao] del servidor:

    
// fabricante
  constructor(axios, phpSessionCookie) {
    // biblioteca axios
    this.axios = axios
    // valor de la cookie de sesión
    this.phpSessionCookie = phpSessionCookie
    // nombre de la cookie de sesión del servidor PHP
    this.phpSessionCookieName = 'PHPSESSID'
  }
    • línea 2: esta vez, la cookie de sesión PHP se proporcionará al constructor de la capa [dao] del servidor de datos;

    ¿Cómo podrá el servidor [nuxt] proporcionar esta cookie de sesión PHP al constructor de su capa [dao]? Almacenaremos la cookie de sesión PHP en la cookie de sesión [nuxt] intercambiada entre el navegador y el servidor [nuxt]. El proceso es el siguiente:

    1. se inicia la aplicación [nuxt];
    2. cuando el servidor [nuxt] realiza su primera solicitud HTTP al servidor PHP, almacena la cookie de sesión PHP que ha recibido en la cookie de sesión [nuxt] que intercambia con el cliente [nuxt];
    3. el navegador que aloja al cliente [nuxt] recibe esta cookie de sesión [nuxt] y, por lo tanto, la reenvía sistemáticamente con cada nueva solicitud al servidor [nuxt];
    4. cuando el servidor [nuxt] tenga que realizar una nueva solicitud al servidor PHP, encontrará la cookie de sesión PHP en la cookie de sesión [nuxt] que le habrá enviado el navegador. A continuación, la enviará al servidor PHP;

    Hay dos cookies de sesión y no hay que confundirlas:

    • la cookie de sesión [nuxt] intercambiada entre el servidor [nuxt] y el navegador del cliente [nuxt];
    • la cookie de sesión PHP intercambiada entre el servidor [nuxt] y el servidor PHP o entre el cliente [nuxt] y el servidor PHP;
